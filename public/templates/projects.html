Concurrent HTTP Server

  • Go
  • React
  • TypeScript
  • SSE

A concurrent Go HTTP server with a configurable worker-goroutine pool, buffered request queue, backpressure, asynchronous logging and graceful shutdown, plus a React/TypeScript dashboard for real-time monitoring over server-sent events.

more screenshots coming soon

A reference implementation of the worker-pool pattern in Go. Incoming HTTP requests are wrapped into tasks and pushed onto a buffered channel; a fixed pool of worker goroutines pulls tasks off that queue, so load is bounded and the server pushes back instead of falling over when it is saturated. Logging runs on its own goroutine so request handling never blocks on file I/O.

A React and TypeScript dashboard connects over server-sent events and shows queue depth, which workers are busy and a live feed of jobs as they are processed.

Highlights

  • Configurable pool of K worker goroutines (default 4) reading from one shared channel
  • Buffered request queue with backpressure when it fills
  • Dedicated asynchronous log writer fed by its own buffered channel
  • Logging, CORS and panic-recovery middleware
  • Server-sent events for real-time job notifications
  • Health check and queue-status endpoints
  • Graceful shutdown that drains both queues and stops the workers
  • All settings (workers, buffer sizes, timeouts, port) via environment variables, with unit tests

Request flow

request -> middleware (log) -> queue -> worker -> response
                                  \-> log channel -> log writer -> logs.txt
                                  \-> SSE broadcast -> dashboard

Persistent Latent-State LLM

  • Python
  • MLX
  • PyTorch

An experimental transformer architecture with a recurrent latent state that persists across inference calls, enabling non-tokenized memory and iterative latent reasoning. I evaluated information persistence, self-modeling, and affect-like modulation of model behavior.

click for details →
screenshots coming soon

The question: can a language model carry a memory from one conversation to the next in a single number, with no text? After an interaction, a small value is read from the model's internal activations and the text is thrown away. In a later, unrelated interaction that value is written back into the model, and if the output shifts in a predictable way, the number carried information. The model's weights are never changed.

What I measured

  • Whether the stored value can be read as a meaningful direction (sentiment), on held-out sentences
  • Whether writing it into a later layer steers the next response, against random-direction controls
  • Whether the effect fades after unrelated turns at a set rate
  • Whether a small learned relay can hold a four-code memory across interactions

Results on Pythia models

  • Sentiment direction held-out accuracy: 86% on pythia-160m, 98% on pythia-410m
  • Steering effect of a stored value on a later prompt: +1.03 (160m) and +2.48 (410m), against about zero for a random direction
  • The larger model passes all 9 persistence checks; the smaller passes 7 of 9
  • Learned four-code memory: 100% held-out recall against 25% chance

GPU Artificial Life Simulator

  • Rust
  • wgpu
  • WGSL

A GPU-accelerated artificial-life simulator supporting thousands of autonomous neural agents, with compute-shader inference, spatial partitioning, genetic evolution and NEAT-based topology evolution for emergent ecosystem simulation.

click for details →
screenshots coming soon

A simulation of a small ecosystem in which thousands of agents act on their own, each controlled by a neural network. The simulation runs on the GPU through wgpu: agent brains are evaluated in WGSL compute shaders, so the population can grow far beyond what a CPU loop handles in real time.

Highlights

  • Thousands of autonomous agents, each with its own neural network
  • Neural network inference in WGSL compute shaders
  • Spatial partitioning so agents find their neighbours without checking everyone
  • Genetic evolution of agent behaviour across generations
  • NEAT-based evolution of network topology, not just weights
  • Written in Rust
